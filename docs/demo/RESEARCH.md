# Онлайн-демо Translator: исследование

Дата: 13.10.2026. База: `mac`, `9ccf0ad0c3536e18a77f53fe488341d55dc4b08d`.
Задача: посетитель пробует перевод без установки, в рамках существующего лендинга. Предыдущие задачи по README, видео и памяти пользователь передал другой сессии; в этом исследовании они не возобновляются.

## Вывод и рекомендуемый путь

Готовые шаблоны лендингов существуют. Ближе всего по структуре AstroWind: FAQ, блог, ссылки GitHub, Releases и обратная связь. Но текущий `site/` уже имеет подходящую основу: системную типографику, светлую/тёмную тему, одну колонку, синий акцент и утверждённые assets. Рекомендация — расширять его, используя шаблоны как структурные примеры. Перенос чужого оформления, Astro/React/Tailwind или аналитики для этой задачи не нужен.

Настоящее приложение macOS можно показывать и управлять им через браузер посредством удалённого рабочего стола. Для этого потребуется отдельный Mac, клиент передачи экрана и сервер управления сеансами. Сам HTML-шаблон эту инфраструктуру не создаёт. Текущая страница статическая; публичный demo-host, session API и доступный URL не подтверждены.

Более простой альтернативный путь — веб-интерфейс к действующему движку перевода и базам. Он позволяет посетителю вводить текст и получать реальные ответы, но не запускает SwiftUI-приложение в браузере. Выбор этого пути нельзя делать молча вместо запрошенной macOS-версии. Вопрос о формате демо отправлен пользователю отдельно.

## Что показал текущий код

- `site/index.html`, `site/style.css`, `site/app.js`: статический русский лендинг с реальной записью. Session broker, VNC/WebSocket client и веб-API перевода отсутствуют.
- `macos/Translator/Sources/Translator/SelectionCapture.swift`: захват выделения через Accessibility либо синтетический ⌘C. В онлайн-сеансе выделение должно происходить на удалённом Mac, а не на компьютере посетителя.
- `translate_logic/infrastructure/providers/apple.py`: длительно живущий Swift helper, Apple Dictionary Services и Translation.framework. Этот путь нельзя перенести на обычный Linux-сервер как Python-функцию.
- `desktop_app/platform/macos/ipc/server.py`: локальный Unix socket, NDJSON, права `0600`. Это не HTTP API для публичного браузера; открывать этот socket наружу нельзя.
- `translate_logic/application/pipeline/translate.py`: общий async pipeline принимает текст, источники и базы. Для отдельного web-demo можно использовать этот слой через новый ограниченный HTTP adapter. На Linux Apple-источники должны быть честно недоступны.
- Старый [DB checkpoint](../presentation/RESEARCH.md) установил происхождение нескольких корпусов и незакрытые права публичного использования. Сам факт наличия SQLite-файлов и MIT-лицензии кода не разрешает автоматически выдавать весь корпус через публичный сервис. Выбранные данные и источники требуют отдельного решения.

## Настоящий macOS-сеанс

Предлагаемая цепочка: текущий лендинг → страница демо → session broker → защищённый браузерный viewer → отдельный Mac с Translator.

Для первого технического PoC подходит [noVNC](https://github.com/novnc/noVNC): браузерный RFB-клиент с WebSocket, клавиатурой, мышью и масштабированием. Его [API](https://novnc.com/noVNC/docs/API.html) позволяет встроить viewer в собственную страницу. Проверенный npm package `@novnc/novnc` — `1.7.0`, MPL-2.0 для core; остальные файлы имеют отдельные лицензии. Пакет пока не устанавливался. `websockify` может обеспечивать переход WebSocket → VNC; авторизацию и выдачу сеансов сам viewer не заменяет.

Альтернатива — [Apache Guacamole](https://guacamole.apache.org/doc/gug/guacamole-common-js.html): готовый стек удалённого доступа с клиентской JavaScript-библиотекой. Он полезен, если уже есть Guacamole инфраструктура. Для единственного демо добавляет больше серверных компонентов. Совместимость конкретного VNC-сервера с macOS 26, ввод сочетания клавиш и скорость экрана должны проверяться на выбранном хосте; наличие API этого не доказывает.

[Appetize](https://docs.appetize.io/) документирует iOS/Android, а не этот desktop macOS build. [BrowserStack Live](https://www.browserstack.com/support/faq/live/test-session/i-want-to-test-a-native-windows-or-macos-app-is-this-possible-to-do-in-live) предназначен для сайтов, а не установки произвольного native Mac-приложения. Эти сервисы не выбраны как готовая замена Mac-хосту.

### Зависимости размещения

Нужен отдельный Apple Silicon Mac с подходящей macOS, подготовленным Translator, словарями/языковой парой и демонстрационными данными. Рабочий Mac пользователя и его текущие grants, историю, Anki и профили для публичного доступа не использовать.

[Лицензия macOS Tahoe](https://www.apple.com/legal/sla/docs/macOSTahoe.pdf), §2I, различает просмотр и управление: ограничивает одновременное управление графическим сеансом и отдельно регулирует service bureau/time-sharing. Поэтому очередь «один посетитель за раз» сама по себе не доказывает разрешённость публичного сервиса. Перед публикацией нужно подтвердить условия именно такого использования с выбранным поставщиком/лицензированием; технический PoC этого не решает.

[AWS EC2 Mac](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/ec2-mac-instances.html) — реальный вариант Mac-hosting, но Dedicated Host имеет минимальное выделение на 24 часа. Актуальная стоимость, регион, доступность нужной macOS и разрешённость публичного demo-use не проверены; закупки/аренда не выполнены.

## Контракт страницы в существующем стиле

Планируемый route — `site/demo/`, относительные assets поддерживают root/subpath. До готового backend публичная кнопка «Попробовать» не должна обещать действующий сеанс.

1. Существующая навигация: Mono logo, Translator, GitHub, ссылка назад на лендинг.
2. Короткий заголовок и одно предложение: что пробовать и что установка не требуется для онлайн-сеанса.
3. Одна центральная область реального viewer. Без имитации macOS, вымышленных результатов перевода и анимированных mockups.
4. Кнопка запуска до подключения; после — завершение сеанса и оставшееся время. Скачивание остаётся отдельной ссылкой.
5. Три кратких FAQ: что работает в демо, чем отличается локальное приложение, что происходит с введённым текстом. Ответы о приватности и доступных источниках пишутся только после реализации соответствующего поведения.
6. Обратная связь ведёт в существующие Issues. Опрос не требует регистрации или отдельного SDK; добавляется после выбора места хранения ответов.

System/SF typography, прежние blue/neutral tokens, одна колонка, текущий spacing и light/dark остаются. Не переносить Inter из GitHub card или типографику/палитру шаблона. Keyboard/focus, 390 px, reduced motion, contrast и доступный статус подключения — обязательные сценарии. Не применять новые библиотеки только ради оформления.

## Серверный контракт для реализации

Ниже — проектируемый контракт, **не существующие endpoints**.

| Операция | Требование |
| --- | --- |
| `POST /api/demo/sessions` | Выдать изолированный сеанс либо явно вернуть unavailable/capacity. Один запрос посетителя не должен запускать неограниченное число Mac-сеансов |
| `GET /api/demo/sessions/current` | Состояние `starting / ready / unavailable / expired`, время истечения и capability mode; `ready` только после worker healthcheck |
| Viewer / WebSocket | Только выданный сервером сеанс; проверка Origin и полномочий при handshake. VNC password не передаётся в HTML, URL или public config |
| `DELETE /api/demo/sessions/current` | Идемпотентно завершить управление; cleanup выполняется сервером даже после закрытия вкладки |
| Timeout / disconnect | Короткий lease, ограниченный reconnect того же посетителя; серверный expiry, а не только JS countdown |
| Следующий посетитель | Только после подтверждённого reset: история, clipboard, временные файлы и демонстрационный Anki предыдущего сеанса отсутствуют |

Нельзя выдавать всем один управляемый desktop или считать CSS-кроп экрана изоляцией. В visitor environment не должно быть личного Apple ID, Finder-доступа к данным владельца или привилегированных приложений. Полный desktop streaming требует отдельной проверки границ управления и изоляции; browser sandbox не ограничивает действия внутри удалённого Mac.

Для альтернативного web-demo: async adapter к общему pipeline, фиксированное en→ru, ограничение длины текста/времени/конкурентности, read-only доступ к разрешённым данным, явный no-match/provider unavailable, отсутствие логирования исходного текста по умолчанию. Browser не скачивает SQLite-корпус целиком. Копирование результата — локальное действие; связь с личным Anki посетителя через интернет не обещается.
